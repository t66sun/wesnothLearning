# 验收计划

> 语言：[English](TEST.md) | 中文

更新日期：2026-11-01。本文件只保留仍未完成的验收工作。已验收事项整项离开本文件，作为带日期的证据留在 `verification/`；`docs/architecture.md` 描述当前实现，而不是其验收历史。

每个事项说明哪些内容仍未完成、能关闭它的最小 Ubuntu 流程、通过标准与证据路径。状态用词：**PASS**、**FAIL**、**NOT RUN**、**REUSED**（身份匹配的既有证据）。无法运行的检查记为 NOT RUN，永不记为跳过的通过。有界烟测自身声明对棋力不充分；本文件中的任何事项都不授权采集、正式训练或调参。

## 边界与共享输入

- Ubuntu 为验收环境，Windows 仅作参考。在隔离目录或临时 run 中工作。冻结输入、manifest、证据与已安装模型保持只读。
- 只激活所有者发生变更的事项。每处行为变更都需要一条被回退即失败的断言；缺少夹具或运行环境即 NOT RUN。
- 复用已验收证据，不要重复。不因代码搬动就重跑完整阵营/规则/worker/种子矩阵、新语料、长收敛实验或压力测试。
- 派生夹具只准备一次，带父哈希，且不修改历史证据。小链条只证明接线，不证明质量、晋升、收敛或棋力。

## L1 —— 缩减全链路运行

**状态：** 2026-10-31 在 Ubuntu 主机上 FAIL，在恢复后的 Astra 路线上重测（`master` `5ac67d9`）。面板、PPO 更新、停止/恢复、选中检查点/导出记录与同未来条款通过；final 评估仍未产出任何可比对局。实测：40/40 场 duel Astra 教师对局完成（4,139 条合格行），5 个 BC 批次（268 次更新）未达到模仿门（准确率 0.401，交叉熵 2.300，均匀分布 4.388），按记录理由强制进入 PPO，7 个批次每次 6–8 次已应用更新；SIGINT 被忽略，`applied=3`（version 8，第 8 批待训练）时 SIGKILL，恢复后到 `ppo_complete`（version 12），未重算第 0–7 批。未中断的孪生运行应用了同样的 7 个批次，第 8–11 批完全一致，同未来条款因此可证实并通过。120 场 final 全部以 `turns 1` 的 `watchdog_timeout` 失败：导出策略单次决策约 1.9 s，而 `vendor/arena/params.py:8` 固定 `ACTION_TIMEOUT = 1.0`；选中项回退为 `last_ppo.pt` v12，其导出已记录。该原因已修复——导出插件带 `score_limit=24`，打分器把与候选无关的输入提到循环外，8 场针对导出策略的 duel 对局全部正常结束、单次决策最多 234 ms（`verification/action_budget_20261031/REPORT.md`）——因此本项剩余步骤是重跑评估，状态为 NOT RUN，需明确指令。

**流程：** 在隔离源码树上冻结一份 lite 配置，使用能到达 BC 的最小面板、至少两次实际提交的 PPO 更新、一次从已提交批检查点恢复，以及 final 评估入口。启动前记录计数、种子、manifest 与检查点身份。每 30 分钟查看状态/日志并保留异常；运行期间不得提高对局数、降低门禁或修改冻结证据。

**通过：** 运行到达 final 评估；两次 PPO 更新均提交；从保存边界恢复在身份一致处精确复现未中断的未来；选中的检查点与其导出被记录；每个停止原因都被报告而非隐藏。缩减面板的限制保持对棋力不充分，失败仍是失败。

**证据：** `verification/acceptance_20261031_astra/REPORT.md`，含身份、停止/恢复边界、第 8–11 批的同未来比对、选中项与导出记录、原版预算故障及其修复（`verification/action_budget_20261031/REPORT.md`）；`verification/acceptance_20261031/L1/REPORT.md` 仍作为恢复前那次运行的记录。

## R3 —— 适配后教师棋力证据

**状态：** 棋力验收仍 OPEN。减速收益排除死亡结果后的完整原版面板完成 168/168 局、零故障，三赛制均有 12 个有效区块和 12 个不同场景族。三个比较仍不充分：duel 的 95% 区间为 [-0.75, 0.75]，ffa4 为 [-0.121528, 0.131944]，team2v2 为 [-0.375, 0.1875]。53 局达到回合上限；候选截断计数不能衡量对局是否自然结束。维护中的教师遇到原版伏击返回码 2005 会停止旧计划，使用被攻击目标的伤害估计计算减速收益，并排除死亡目标的减速奖励。两个独立评分反例均有修复前失败、修复后通过的原版和 Lite 选武器证据。零击杀概率的目标归因对照及未改变的查询/战斗证据复用。战术检查和零故障面板均不能证明棋力保持。

**流程：** 复用已完成面板和固定局面证据，不重复未改变的对局。教师变更需要具体诊断，并预先声明相互独立的开发／验证设计。保留 12 区块／12 场景族匹配契约、完整座位轮换、两种队友上下文、冻结对手和最终 holdout 预留。截断或块数不足的棋力证据仍不充分。当前评分器以区间下界 > 0 判断显著优越；“保持棋力／非劣效”尚未声明容差，须在新的此类实验之前明确，不能根据本次结果倒推。

**通过：** 烟测能发现明显的战术或运行时退化，但不声明统计非退化；完整棋力结论需要完整匹配面板且 hold-out 预留未被触碰。否则状态保持未验证，应修正假设而不是一直加种子直到赢。

## 执行与报告

1. 确认变更所有者、激活事项与可复用证据。预先声明行/窗口/步数/对局上限与数值容差；只实现需要的断言或助手；运行前记录真实命令。
2. 先跑受影响的本地确定性检查，再跑相关 Ubuntu 检查。真实对局只在该事项被激活并另行授权后启动。
3. 受影响检查通过即停止；修复后只重跑失败用例及其变更依赖。

一份带日期的 `verification/acceptance_<date>/REPORT.md`，仅在用到时创建产物子目录：

```text
Scope: 行为/提交；激活事项；排除项与原因
Identity: 源码/扩展构建、Ubuntu/Python/torch、catalog/profile/teacher/schema、
          输入/模型/优化器哈希、种子/计划/游标（如相关）
Commands: 可执行命令、cwd、参数、退出码、耗时
Results: 用例 | PASS / FAIL / NOT RUN / REUSED | 断言/计数 | 产物
Reuse: 原报告 + 身份匹配；复用不是新运行
Failure: 首个不同输入/步骤、期望/实际、复现方式
Resources: 行/窗口/族/解码/步数/子进程；相关时峰值 RSS/PSS
Gate: 可进入指定下一阶段 / 被阻断；缩减面板不充分
Limits: 未写的测试、缺失输入/运行时、未证的质量/棋力
```

证据中不得包含凭据。失败、缺失必需观察、静默跳过或身份不匹配都会阻断受影响事项的验收。纯文档变更只跑文档、链接与差异检查。本计划没有运行时结论。
