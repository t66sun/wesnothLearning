# PPO 效果排查与原版 AI 替换计划

> 语言：[English](ppo_diagnosis_plan.md) | 中文

日期：2026-10-26。状态：**初步静态分析完成；下面的动态排查、实现和验收均未执行**。本轮仅阅读当前源码、已下载 manifest/summary 和既有证据，不连接服务器、不运行模型推理或优化器、不采集新对局、不启动训练。静态观察及可复算数据见[报告](../verification/ppo_static_review_20261026/REPORT.md)。

用户已决定后续把 Astra 全部替换为 Wesnoth **1.18.8 原版默认 RCA AI**。这是新的目标，覆盖旧架构中“唯一教师为 Astra”的后续运行约束；当前实现仍使用 Astra。替换与 PPO 根因排查分开归因，不能把同时换教师、引擎、随机机制后的结果全部算作 PPO 修复收益。请求及决策跟踪见 [#48](https://github.com/t66sun/wesnothLearning/issues/48)。

## 2. 五个优先突破点

### H1：有效局面可能远少于局数，BC 验证与评估独立性存疑——最高优先

**事实：** `schedule.factions` 以 `block×players` 在六阵营中循环；评估固定地图循环。lite 初始领袖、位置、属性固定；战斗为确定性期望伤害，Rust 核心没有消费 seed 的随机流。`game_family` 却把 seed 放入哈希，再以哈希的模 5 结果划分训练/验证。当前最终 30 个 block 的分差，Duel 严格每 6 块重复，FFA4/2v2 严格每 3 块重复。

**假设：** 同一个物理场景、甚至同一教师轨迹，仅换 seed/编号就进入不同 family 和不同 split，使 BC 验证偏容易；重复评估块可能被当成独立样本 bootstrap。训练还可能过度记忆少量阵营组合、地图和座位。

**不能直接推出：** 相同分数不等于相同轨迹；学生采样、对手身份、预算和执行顺序仍可能使轨迹不同。先核验，再决定数据切分或统计是否需要修复。

**突破信号：** 跨 train/validation 出现相同规范化合法输入与教师动作序列；或多个 final block 具有相同场景和逐步轨迹。若仅有相同结果而输入/轨迹不同，撤回“重复轨迹”判断，保留有限场景覆盖问题。

### H2：PPO 每批有效学习量不足，或单次更新导致策略跳变

**事实：** 先前进度观察中出现过少数 optimizer steps 后 KL 早停；本轮尚未重算完整 run 的 PPO 分布。当前 `ppo.update` 在每个逻辑 batch **更新前**检查 KL，阈值 0.02；检查的是该批数据，不是全 rollout 的最大偏移。损失同时包含 clipped policy loss、0.5×value MSE、entropy 和 BC 辅助项；共享编码器都会收到梯度。BC→PPO 沿用 Adam 状态，只把学习率改为 1e-4。

**假设：** 一是 rollout 保存的行为概率与更新前重放不一致，起点 KL 已异常；二是某次已提交更新，尤其价值/BC 梯度或 Adam 状态，让策略在下一批上偏移过大，触发早停。PPO clipping 不自动限制另外几个损失引起的策略变化。

**突破信号：** 零步重放已不一致，优先修输入/记忆/概率合同；若零步一致、一步后固定探针 KL 跳升，追查具体梯度与更新。若有效遍历正常且 KL 受控，就降低此方向优先级。不能把“触发保护”本身认定为缺陷，也不能提高 KL 门槛来掩盖。

### H3：奖励、价值与时间归因可能给错或给弱学习信号

**事实：** 当前 gamma=1、GAE lambda=0.95；同一 own turn 内多动作不重复折扣。经济/控制采用 potential difference，真实终态清零后继 potential；回合上限截断保留合法 bootstrap。优势按全体 decision 标准化，优化时每个八 own-turn window 等权，window 内各 decision 等权。

**假设：** 大量截断、过长轨迹、价值误差，或少数终局奖励使优势信号不稳定；同回合长动作链的归因和窗口权重也可能让关键招募/攻击被稀释。归一化和目标权重采用不同单位，是需要测量的选择，静态上不能直接判错。

**突破信号：** 手算序列与程序回报不符；完整轨迹缺尾、terminal/truncation 标错；critic 对截断回报系统性偏差；或分动作/阶段的优势和有效权重明显集中在无助于胜负的动作。potential 项在 gamma=1 的真实终局轨迹上有望远镜求和性质，不应仅凭逐步数值小就判定无用；GAE、critic 和截断仍需分别检查。

### H4：教师缺陷、BC 泛化与候选空间限制相互叠加

**事实：** 四人 Astra 招募用固定兵种权重、己方数量惩罚和少量可见敌军抗性启发式。PPO 仍以 BC 辅助损失回放同源标签，教师同时充当固定对手、2v2 队友与自适应奖励参考。候选生成独立于教师答案，但存在 20,000 工作预算、128 候选上限、每兵种最多 8 个招募位置等限制。2v2 BC 门的招募 93.02% 只来自 43 条样本。

**假设：** 高模仿率复制了教师招募缺陷；学生在自己的状态分布上失误，BC 参考又限制其偏离；或关键合法动作在剪枝后不可选。用户观察足以把替换教师列为目标，尚不足以证明它是 PPO 效果不佳的唯一原因。

**突破信号：** 分类区分“好动作不在候选中”“候选存在但模型选错”“教师本身选择不佳”。查兵种选择与位置选择、阵营/地图/座位/时段/队友语境，不能把三类错误一起算成网络精度问题。不能按原版随机战斗的直觉直接给 lite 的确定性对局判战术错误。

### H5：最终选拔、评估域与训练目标之间的差异遮住了真实变化

**事实：** 最终 selected 与 latest 不同，FFA4 最新候选未完成提名。完整 promotion 每 100 版本才进行，常规趋势面板较小且轮换布局不同。`selection_key` 可以记录负分冠军，它代表候选中的相对最好，不代表已胜过固定对手。当前最终只评 lite Astra；安装后的原版游戏使用不同战斗语义。

**假设：** “PPO 没提升”部分来自拿不同 checkpoint、不同布局或不同引擎作比较；也可能确实在相同面板上退步。需要先分开测量，不能以部署体验替代 lite PPO 的因果诊断。

**突破信号：** 对齐版本、方法、控制方和完整面板后仍持续下降；或发现下降只来自换了面板/selected 保留较早模型。二者应报告为不同问题。最终 holdout 保持只读，不拿来挑参数或追选模型。

## 3. 排查步骤与停止条件

所有未来工具、断言和动态步骤目前均为**未编写或未运行**，不是已通过的测试。后续先本地，必要时经明确授权在 Ubuntu 新隔离目录最小验收；不得覆盖原 run、规则包、manifest、报告或检查点。每一步先冻结输入哈希、资源上限与预期，再执行。

### S0：建立可追溯的诊断账本，不新增对局

1. 固定本次 source、extension、catalog、feature/candidate、teacher、combat/RNG、reward config、模型与优化器身份。先复用本地 summary/manifest/selection；仅当本地缺少必要原件时，单独提出服务器只读取证范围。
2. 按赛制、BC/PPO、版本列出：采集局数、有效/故障/截断局数、teacher/DAgger/human 来源、train/validation family、planned/inspected/committed decision 和 window、optimizer steps、KL/deadline 停止、各阶段用时。
3. 将已结算 history 与 `pending_train.cursor` 分列；同一累计 cursor 不能每次保存都求和。核对计数守恒和日志中的 actual update，不能用版本号或用时替代训练量。PPO 按 family 哈希也会剔除 validation split，统计实际排除数量，不假设每批恰好 20%。
4. 记录 BC 最后完整版本、首个 PPO、promotion、last/best/selected；标明方法。重用已有匹配布局的 validation/champion panel，不补 holdout。
5. 输出 `inventory.json`、`exposure.csv`、`checkpoint_lineage.csv` 和缺失原件表。原件不全则相关结论标“无法判断”，不默补。

**退出条件：** 能把一次采集追到实际已提交学习和最终选择；无法对齐身份/计数的格式先停止数值归因。主诊断优先 Duel，其最终负分明确、轨迹较小；2v2 用来核验招募/团队特有结论，FFA4 在需要验证四人差异时才展开。

### S1：检查真实多样性和验证泄漏——H1

1. 先读已有 schedule/index 元数据，覆盖全 run 的地图、阵营组合、座位、队伍、伙伴/对手及权重身份、max_turns、fog/sharing、地图 hash，列出组合覆盖和重复次数。
2. 为重复簇定义两个**诊断用**指纹，不改原 family：初态/规则/控制策略指纹，以及合法观测→候选有序列表→教师意图/实际执行→记忆写入的轨迹指纹。只排除 game_id、路径、seed 等纯身份字段；保留实际影响决策的采样状态、AI 状态、单位对应关系、时限/工作预算。若 ID 重命名必须保持 actor/target 引用一致，保留规范化映射供复核。
3. 第一轮仅解码每赛制最多 6 对可疑重复 teacher family：同图同阵营同角色，优先跨 train/validation；含完整前缀，比较首个差异。检查同一物理初态是否仅因 seed 被划到不同 split。样本未发现碰撞不等于全语料无泄漏；若发现一对真实碰撞，再仅扩展该簇的索引核对。
4. 对 final 已有轨迹，先每赛制比较 1 对相隔 6/3/3 的 block，包含其全部座位轮换/团队语境，**不重打比赛**。若原轨迹不在本地，标待取证。分数周期不能替代轨迹指纹。
5. 若重复得到证实，另出按真实场景聚类的诊断统计与有效独立簇数；簇很少就只描述已观测固定场景，区间标不足。不得覆写原 30-block 结果、暗改最少 block 数或把诊断统计冒充新验收。
6. 仅在证实碰撞后设计新语料 split：物理等价场景/轨迹同组、train/validation/holdout 不交叉；新 schema/数据目录，旧数据原样保留。补一个“同局面不同 seed 不得跨 split”的反例断言；改进场景覆盖须另行冻结方案，不能现在任意加地图和对局。

**输出/停止：** `scenario_coverage.csv`、`duplicate_pairs.json`、首差异/规范化说明；碰撞为零或仅分数重复则不实施去重修复。若有泄漏，旧 BC 高精度只保留历史含义，后续新数据重验原门，不宣称已重新过门。

### S2：先做零更新的行为概率重放——H2 前置

1. 从 S0 找一份有**原始行为权重**、完整合法前缀、候选顺序、动作、old log_probability/value 的冻结 PPO batch。不能用 selected 替代产生 rollout 的权重；原件缺失就换另一完整 batch，仍缺则报告阻塞。
2. 首轮仅 Duel 一批，取早/中/晚段共最多 48 个 target，涵盖 recruit/move/attack/end_turn、own-turn 边界与超过八轮的历史。保持完整 raw prefix；不因目标少而裁掉前缀。
3. 对比实际 `FrozenPolicies.choose` 单条/缓存路径与 `model.batch` 训练路径；检查权重 hash、候选 mask/索引、float32 张量、动作的执行 intent、一次且仅一次 memory commit、重放 reset、sampling/greedy 模式及模式切换。
4. 不更新参数，输出每条 chosen logp/value 差、ratio、分布 KL（若记录了完整旧分布）、实际使用的 sampled approximate KL、各路径张量差与首差异。未记录旧全分布时不能反推“精确 KL”。先按相同输入的 1e-5 输出差门及 ratio 接近 1 检查，近零概率另外记录相对敏感性；任何容差变更必须给依据，不为让数据通过而放宽。
5. 任一差异先沿“原始 row→prefix→batch→context→logits→概率”二分定位。零步异常时停止后续 optimizer 归因。只有这里通过，才进入 S3。

**输出：** `replay_parity.json` 和最小完整前缀反例。若修复，断言必须在还原修复后失败；既有重放优化测试证据仅复用其原覆盖，不能充当此次真实 batch 的结果。

### S3：两步离线更新定位策略跳变——H2

1. 复制 S2 的 model、Adam、RNG、数据/window 顺序和 BC 样本计划到独立诊断目录；全部副本可丢弃，原 checkpoint 不写回。使用同一固定探针，在零步、每步前后和下一逻辑 batch 上测 KL、ratio 分位数、clip fraction、熵、动作变化和 value explained variance。
2. 对共享编码器、GRU、actor head、value head 分别测 PG/value/BC/entropy 梯度范数与两两余弦、裁剪前总范数、裁剪系数、参数实际变化。记录 advantage/return 分布、value MSE、loss 项；loss 数值大不等于梯度影响大。
3. 首先只跑完整目标的最多 **2 个已提交 step**。若复现跳变，再根据梯度证据选最多 2 个单因素对照：例如去 value 梯度、去 BC 梯度、或仅在 BC→PPO 首步比较继承/新 Adam。每臂仍最多 2 步、同一探针/窗口/RNG；不做全部组合网格，不改生产配置，不把消融副本当训练模型。
4. 区分“本步后全探针偏移”“下一个 batch 自身分布更难”“稀有动作 old logp 放大估计”。KL 门原样保留；诊断若被门拦截即记录拒绝，不绕过以凑步数。报告计划步数/实际提交数。
5. 只有证据指向具体原因才提出最小修复：输入合同错误先修合同；梯度/Adam 路径问题单独 PR；若仅需调参，先明确诊断结论再提出一个变量的方案。不得同时改 LR、奖励、网络和采样规模。

**退出条件：** 找到第一个偏移步骤及主导因素，或清楚记录该冻结 batch 无法复现。通过两步检查只证明局部更新机制，不证明收敛。Duel 结论只对 2v2 一个已存在冻结 batch 做必要交叉核验，不自动展开三赛制矩阵。

### S4：奖励、bootstrap、GAE 与窗口权重审计——H3

1. 复用奖励/GAE 已有断言，补足实际缺口；先用两条极小序列手算：一条含同回合多个 decision、下一 own turn、真实胜/负终态；另一条在回合上限截断，有明确 bootstrap value/potential。把平局、FFA 中心化名次、2v2 本方领袖先死而队友存活作为必要边界变体。
2. 逐项对比 terminal/economy/control/explore、delta_turn、TD residual、GAE、return，检验势函数求和、探索只计新增、终态吸收与截断保留。PPO 的奖励可用裁判真值，但 actor/teacher 输入及 bootstrap value 仍只看合法信息。
3. 从 S2 同一 batch 审查完整 game/side 序列是否缺中间/尾部、排除是否以完整 family 为单位；统计回合长度、终局/截断占比、各动作/阶段 reward RMS、advantage 正负/离群、value 预测与真实回报。不能把少数 target 当完整轨迹计算 GAE。
4. 为每个 target 输出实际优化权重 `1 / (本 batch window 数 × 本 window decision 数)`，对比 decision 标准化及各动作的 committed 暴露量，判断长动作链、长局、终局和招募的实际权重；同时统计窗口覆盖与 KL 拒绝位置。
5. 审查已记录 reward controller 版本、参考来源、完整窗口和控制事件，确认旧滚动窗口修复存在；原版替换后不得把旧 Astra 校准继续用于新 RCA。**本阶段不改系数或添加“提前结束惩罚”**。

**退出条件：** 有手算不符/缺尾就最小修复并补反例；信号弱但实现一致则报告为待控制实验的学习假设。新 native 终态路径必须完成 [TEST N1](TEST_zh.md) 的既有缺口，不复用 lite 结果充数。

### S5：招募与行为错误分解——H4，同时澄清 H5

1. 优先看用户遇到的招募回放或已有失败局，最多 12 个合法决策上下文：六个招募、三个移动、三个攻击/结束回合；缺某类就报缺失，不新增对局凑齐。给出地图、阵营、队友语境、金钱/城堡连通性、时段、可见敌军、兵种库存、候选和实际动作。
2. 对招募拆成“能否招募”“单位类型”“落点”“后续运输/参战”；保留教师原意与执行结果。检查理想候选是否合法、是否在 128 上限/工作预算之前被排除；不允许把教师答案直接插入 actor 候选以伪造覆盖率。
3. 用已有规则的可手算局部条件解释错误；原版 RCA 的未来建议只作同一 native 上下文参照，不当万能正确标签。模型复制教师错误、模型偏离教师、teacher intent 无法表示须分列。合理等待/保命的 end_turn 不按“还有移动力”自动判错。
4. 分阵营、地图、阶段、来源和真实场景簇重算已有 BC 覆盖/精度，报告分母和独立簇数，特别注明 2v2 的 43 个招募验证样本；不写成 93% 棋力。
5. 用已有**匹配** panel 对齐 last BC / PPO / selected 的表现和选择理由。没有可比 panel 就标缺失，提出后续只在 validation 上的最小配对方案；不复用 final holdout 调参、不临时补测并追选。

**输出：** 最多 12 张动作反例卡、分层误差表和 checkpoint 比较账本。是否需要改候选或监督目标，以具体反例决定；不在本次继续打补丁优化 Astra 的招募。

## 4. Astra 全量替换为原版 RCA 的实施路线

### R0：先验证能力，不把“换名称”当替换

当前 `lite_host` 明确拒绝 baseline；`experiment.execute` 会把 lite 的 baseline 改成教师 Astra。`teacher_jobs`、manifest、样本验证器、数据采样、native collector/DAgger、reward reference 等也硬编码 Astra。即使设置 `engine=native`，教师查询仍加载 `gpt6astra/lua/*.lua`，固定对手列表也仍包含 Astra。

原版 baseline 是原版进程中的默认 RCA，含原生候选动作实现；现有 Lua wrapper 拦截的是 Lua `ai.move/attack/recruit` 等调用，**没有证据表明它能捕获默认 C++ RCA 的全部动作**，也没有已验收的“只读下一动作”接口。

1. 静态追踪 1.18.8 default AI 配置、C++/Lua CA 及招募实现，明确实际默认配置、参数和可采集接口；只改外层接入，不自行重写一套“近似原版”策略。
2. 推荐先以真实 native 进程运行原版 RCA，证明完整动作采集和只读查询。忠实原版依赖 native，吞吐和随机战斗语义与 lite 不同；仅改字符串无法在 lite 运行原版。
3. 若希望保留 lite 高频采样，必须另行证明原版 CA 可复用，并在同一合法可见上下文上对齐决策/实际规则和身份；做不到就明确标为不支持，不暗退回 Astra 或自写简化策略。本计划不默认批准大规模移植原版 C++ 引擎。
4. 新教师身份建议独立为 `wesnoth_default_rca`，冻结 exe/version/build、default AI 配置及可获得的实现源/构建 hash、规则、fog/sharing、AI 参数、RNG 机制。`teacher_profile=native` 本身不能证明教师是原版 RCA。原版启动 seed 也不保证逐动作整局重演，重演依据为原版 replay/实际 RNG 记录，裁判数据不送教师。

**能力门：** 原版真实动作可以采集、teacher query 只读且合法、招募语义明确后，才能承诺完整 BC/DAgger 替换。若只完成对手替换，必须标“部分完成”，不能声称全量替换；DAgger 能力缺失时阻塞依赖链，不返回虚假 end_turn、不混回 Astra 标签。

### R1：逐处替换清单

| 入口/职责 | 当前拥有者 | 目标与必要断言 |
| --- | --- | --- |
| 教师/固定对手冻结、manifest、配置验证 | `learning/manifest.py`、`teachers/`、`experiment.py` | 活跃新 run 只认原版 RCA 外部教师/固定 AI；删除 lite baseline→Astra 替代。记录真实实现身份，误传 Astra 明确拒绝 |
| BC 教师局、2v2 队友与 opening probe | `schedule.py`、`sample.py`、`collector.lua` | 实际控制者是原版 RCA；能捕获执行前合法输入、意图、实际结果，含 recruit/move/attack/end_turn；漏捕不能视作通过 |
| DAgger、PPO BC rehearsal | `native_rpc.lua`、`collector.lua`、`lite_host.py`、`experiment.py` | 学生偏离后的只读 RCA 建议；查询不推进游戏、RNG、AI 内部状态或学生记忆；旧 Astra 原始/DAgger 标签不进入新活动池 |
| rollout 固定对手、FFA 补位、2v2 伙伴 | `schedule.py`、`experiment.py` | 所有 Astra 外部角色替换为原版；同赛制 student/history/current 自博弈角色保留。新池不能继承带 Astra 标签的旧训练状态 |
| 奖励参考及校准缓存 | `reward_metrics.py`、`control.py`、`experiment.py` | 原版 RCA 的同布局参考与真实身份，旧 `astra_*` 名称/缓存不冒充新数据；阈值、计算规则与奖励系数不借迁移放宽 |
| trend/promotion/champion/final 与报告 | `evaluate.py`、`schedule.py`、`experiment.py`、`report.py` | 固定控制方改为原版，2v2 分伙伴/自队上下文；冠军比较保留学生历史角色；完整性、预算、安全回退、selected hash 门保留 |
| 样本、分池、检查点、导出、打包 | `data.py`、`sequences.py`、`checkpoints.py`、`export.py`、bundle/文档 | 新教师身份逐层可追踪；Astra/native-Astra/lite-Astra 与 RCA 分别校验；新 manifest 不带 Astra 活跃依赖，旧产物仍可按历史来源读取 |

“全部”指后续活动路径和依赖全部替换，**不是删除历史证据或抹掉旧数据的 Astra 名称**。保留旧包、run、安装和兼容审计；旧权重若将来用于初始化，要明确用户选择及血缘，不能伪装为同源 resume。新默认不加载旧 Astra 语料或旧优化器/RNG/对手池。

### R2：最小验证，不先开正式训练

1. 复用一个最小合法 fixture，覆盖原版招募、移动、攻击、回合结束；允许分步构造，先本地参考，再 Ubuntu 隔离。核对真实原版控制入口与实际动作，而非 mock 仅返回 baseline 字符串。
2. 采集合同断言：每个目标有执行前 obs/candidates、真实 action intent 与执行后结果；部分移动和 move→attack 不能拼错目标；未匹配 intent 留作诊断，不能给 choice=0 伪造 end_turn。候选覆盖必须过原门，否则显式阻塞。
3. 在同一可见上下文下扰动隐藏敌军/未探索地形等裁判信息，核验教师输出不依赖隐藏值；查询前后游戏、可用 AI 状态、RNG、学生记忆一致。若原版入口无法满足只读/信息边界，先解决能力缺口，不能把完整裁判快照传入策略。
4. 配置与身份断言：逐个 teacher/DAgger/fixed-opponent/partner/reference/evaluation 入口解析到原版；混入 Astra 样本、伪标 native 身份、过期参考缓存时必须失败。活动依赖扫描结合实际调用验证，不能要求历史目录没有字符串 Astra。
5. 新 native 路径涉及终态/截断时完成现有 N1，复用预算、选拔、导出身份、PPO 计数与取消恢复等无关已通过证据；只重开受影响合同，不重跑全套。新增测试都要给还原修复即失败的断言。
6. 动作采集/只读查询通过仍不等于全盘战术/棋力通过。短局与三赛制阶段链、是否训练及其时间/规模另行提出明确授权；本计划不启动它们，也不承诺沿用 lite 的 30 小时吞吐。

## 5. 顺序、交付与完成定义

执行顺序：**S0 → S1 → S2 → S3**；S4 复用同一 batch，发现合同错误立即先修；S5 用已有失败局补行为解释。R0 的静态接口调查可同时准备，真正替换放在旧 run 的关键因果证据保全之后。不得为了等原版迁移而跳过 PPO 自身检查，也不得先把整个系统一起改掉再猜原因。

每个已证实缺陷一个窄 PR：反例→失败断言→最小修复→本地→Ubuntu 受影响验收→报告/中英文架构与 TEST 更新。先开调查/能力验证，再按实际依赖拆原版接入、教师采集/查询、其余角色接线；避免先造通用插件框架。未实现诊断留在本计划，已实现待验收事项才进入 TEST。

每阶段新证据至少记录 source/输入/权重/优化器/规则/教师 hash、命令/退出码、数量/资源上限、首差异、PASS/FAIL/NOT RUN/REUSED、复用证据原路径和限制。时间较长但无新证据时停下总结缺口，不反复重跑。

完成根因诊断需要：可复现反例、定位到的首个错误或失效学习机制、排除的替代解释、一个变量修复/对照、还原即失败断言，以及所需 Ubuntu 最小证据。若只是发现相关性，应称为“支持某假设”，不称“已找到唯一根因”。完成 Astra 全量替换需要 R1 全部活动角色与身份验收通过；恢复训练、棋力提高、收敛均为后续单独结果。

本轮产出仅为静态事实与这份方案。未运行：服务器取证、轨迹去重、零步重放、梯度消融、GAE 新 oracle、原版 RCA 能力 probe、新对局、训练和新棋力面板。
