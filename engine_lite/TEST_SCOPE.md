# Lite engine follow-up test scope (not written or executed this round)

> Language: English | [中文](TEST_SCOPE_zh.md)

Currently only Python AST and Lua load syntax checks were done (Lua modules not executed); there is no cargo/rustc, so Rust/PyO3/mlua are not compiled. There is no 1.18.8 release data, no catalog/rules/maps generated, and real full coverage, Astra host compatibility, rule correctness and the 5× performance target are all unaccepted. Standard leadership/illumination/backstab/steadfast, attacker/defender plague and one-step teleport already have explicit approximate implementations; full declaration-condition filtering, random trait generation/retention across upgrades, variant runtime instances and AMLA/upgrade choices, vision_costs/jamming remain code gaps and must be listed separately rather than called merely untested.

## Suggested order and scope

1. Build Rust/PyO3/mlua first; verify package ABI, the vendored Windows Lua build, single and batch JSON APIs, atomic rollback of illegal batch actions and that all errors are understandable. Syntax checks are not a runtime pass.
2. Generate data/executable hash manifests independently from a trusted 1.18.8 release; capture in core and in every bundled campaign context. Verify all declared units, genders/variants, upgrade/plague chains, traits, terrain base/overlay/aliases and the actual counts of the selected maps, plus provenance and scope differences. Report raw WML retention and compact runtime instantiation separately. List exact/approximate/unsupported_script and the reason per ability/unit, refusing silent degradation.
3. Deterministic native differential: odd/even column edge hex adjacency, map coordinates/distances, each movement type, low movement remainder, slowed, ZOC, skirmisher, friendly passage, connected/disconnected castle recruitment, multiple leaders, village-capture exhaustion, teleport/concealment/contact path interruption, rest/poison/healing/income/upkeep, experience/upgrade/AMLA, elimination rotation and team victory. Unsupported features must be explicitly refused, never replaced by ordinary combat.
4. Per-strike hit-injection differential: firststrike/both firststrike, attack/counterattack weapon ties, per-strike death and attack stoppage, immediate slow effect, drain actual damage/rounding, poison immunity, magic/marksman, charge, 30-round berserk, swarm, plague with terrain limits, attacker/defender upgrade. Independently compare hit/death/status probability error ≤1 percentage point and mean HP error ≤0.5 statistically, reporting sample counts/intervals/variance and never mistaking sampling noise for a semantic deviation.
5. Information isolation: changing hidden enemy units/hidden village ownership/unknown terrain must not change public observations/candidates/forecasts or policy inputs; raw referee scalars only feed training labels. Four fog/shroud combinations, non-shared ally/shared map/shared vision/directional sharing, information age/stale enemy records, re-observation after hidden blocking/ambush, rejection of any side switch. snapshot truth is never given to teachers or policies. Candidate/teacher queries consume no combat/recruit RNG and restore the hit-stream cursor and all ledgers.
6. Real Astra zip duel/four planning, candidates from the same Lua O/C/S modules, at most 128 candidates, move/move-attack/recruit/end, clone units/feature access/combat hp_chance integer keys, interrupted path execution, memory commit without a changed action, teacher original intent versus actual endpoint. List missing APIs separately for the native interface and the host shim; Astra must not be replaced by another heuristic. The official baseline stays native.
7. Training label wiring: raw economy/control/explored, deduction of every side's initial visible area, teammate exploration de-duplication, repeated fog reveal not increasing, restored shared ledgers, terminal/truncated bootstrap, full provenance/reward version; policy callbacks never receive reward_only information. Full-game results bots/teams/winner/winning_team/rank_points/survivors must match the native payoff definition. Multi-side elimination ties need explicit ordering.
8. Fixed equal-work performance: single-process cold/hot, same CPU quota/map/units/policy/teacher/action script. Split rule core/shared candidates/real Astra/model/JSON and trajectory IO; count every subprocess CPU core-second. wall and CPU each ≤20% of native, reporting p50/p95, RSS and confidence intervals; 4/8 worker throughput is listed separately. Current full vision recomputation and 128-sample forecasts are potential hot spots and need real profiling before optimization.

## Report format

Save machine-readable JSON plus concise Markdown. Include at least commit, build/dependency versions, 1.18.8 release hash, catalog/rules/maps hashes, engine/rules/RNG/candidate/schema versions, system CPU/memory/thread quotas, samples and seeds, fixture/map/faction/format/position, native and lite inputs, injected hit sequences, expected/actual, deviation category, pass/fail/unsupported/inconclusive, faults and missing-block counts, and reproduction commands.

Sign off separately: P1 definition coverage, P1 deterministic semantics, P1 combat statistics, P2 real Astra host, P2 single-game wall time, P2 total CPU, parallel throughput. Write pending for missing material, uncompiled or unexecuted work; never write passed or zero errors. Only independent coverage and acceptance evidence may update catalog.complete/native_accepted/performance_accepted; unaccepted work must not open long-collection default gates.
