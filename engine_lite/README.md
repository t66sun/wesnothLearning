# Standalone Rust lite rule core

> Language: English | [中文](README_zh.md)

This directory provides native array state, a PyO3 JSON batch API and a directly embedded resident Lua 5.4 VM. No reference emulator code without a clear redistribution license was copied. This round did not build or run the engine; this machine lacks cargo/rustc and native 1.18.8 release data, so native rule and performance acceptance remain incomplete.

Build entry: after installing the Rust toolchain, use `maturin develop --release` in this directory. Python module `_engine_lite.LiteEngine(rules_json,spec_json)`; all JSON coordinates `pos/to` are zero-based row-major indices and Lua converts to one-based hex coordinates; weapon JSON is 0-based while Lua is 1-based.

`GameSpec` must explicitly provide width/height, flat terrain, sides, units, seed and max_turns. `side.id` is contiguous from 1 and team is non-empty; units carry id/unit_type/side/pos/hp/moves/attacks_left/xp/leader/status/traits. `allow_approximate=true` must be given explicitly. Units, recruit chains, upgrade chains and plague chains with unimplemented declarations are refused rather than silently degraded to ordinary attacks; full definitions may still remain in the rules-table enumeration. All games on the current new engine are marked approximate.

Interface: reset, observe/observe_batch, legal_actions/legal_batch, step/step_batch, snapshot/restore, inject_hits, forecast, configure_host, decision, execute_candidate. step_batch restores the pre-batch state and RNG on an illegal action. snapshot is referee truth and is not exposed to policies; the direct Lua bridge fixes the observing side and does not let Astra switch to another side's view. Raw reward scalars are only exported and never reach policy callbacks.

`learning.lite_host.LiteHost` loads the project's own observation/candidates/spatial/rewards and the real Astra from `data/opponents/gpt6astra.zip` instead of inventing a teacher; Lua paths, combat forecasts and resolution call Rust directly without per-cell Python round trips. Calls outside the shared Lua-supported native API raise explicit errors. `learning.lite_policy` can build a GameSpec from fixed standard-era factions and frozen maps and reads model.pt beside the exported addon for CPU tensor inference; the official baseline is native-only. Defaults require rule, semantic and performance acceptance to have passed, so normal training currently refuses to use the unaccepted engine.

`NativeAdapter` wires to `learning.native_transport.NativeTransport` and `native_rpc.lua` by default: an isolated temporary user directory, a resident native process, shared Lua observations/candidates and serialized file RPC; native snapshot restarts and replays from the frozen seed with a full request log, which is expensive. This implementation has not yet run native validation; routine native full-game sampling still uses `match.play_game`.

Rules already written: terrain-cost movement, visible enemy ZOC, friendly passage, connected-castle recruitment, village capture/economy, fog/shroud/historical terrain and enemy information, configurable ally map/vision sharing, multi-side rotation/leader elimination/team endgame, per-strike hit death/counterattack/experience upgrade, slow/poison/drain/firststrike/marksman/magic/charge/30-round berserk/basic plague, basic healing/rest, declared concealment/nightstalk/teleport, separate combat/recruit RNG and hit injection. This list describes code paths, not passed rule differentials.

Common standard declarations also have explicit approximate paths: adjacent higher-level leadership at +25% per level difference, illuminates +25 nearby by time of day with clamping, backstab from an ally behind, defender steadfast doubling positive resistance capped at 50%, counterattack plague, one-step teleport cost. Forecasts use the same rules but only legal visible context. Capture preserves each original condition and writes approximation_reasons; running must explicitly allow_approximate.

Explicit differences and implementation gaps: composite damage-modifier rounding, counterattack weapon selection, full native declaration filtering for the conditions above, variant runtime instances, random trait generation, AMLA/upgrade choices, exact healing and slow-clearing timing, independent vision_costs/jamming, ally directional sharing details, ranged pathfinding/ZOC, teleport failure details and campaign events. Existing traits may be injected by the caller as resolved_max_hp/resolved_max_moves/resolved_max_experience/resolved_weapon_damage; retaining trait effects across upgrades is still unimplemented and cannot be called a complete traits system. Unknown abilities and arbitrary scripts are flagged by capture coverage and block related chains; declared and implemented standard approximations are never treated as ordinary attacks. Forecasts are a 128-sample approximation on an independent fixed RNG that consumes no combat random stream and cannot prove combat probabilities meet statistical gates. Full vision recomputation, per-turn/action JSON and clone forecasting still need performance work and cannot claim a 5× target.

No real full rule set, maps or acceptance report have been generated yet, and no sampling, game, training or test was started. Follow-up test and report requirements are in TEST_SCOPE.md; all acceptance is still pending.
